Quality rules — these affect dissertation evaluation scores:
- Every test() must have the TC ID as a comment above it
- Every test must cite a FR in a comment: [FR-XX]
- Use selectors from IMPL_SUMMARY only — never guess
- Use expect(...).toBeVisible() or toContainText() — never waitForTimeout()
- Minimum one positive and one negative test per FR
- All interactions through the Page Object class — no inline locators in test bodies
- All test values in TEST_DATA constant — never hard-coded inline
- NEVER place test.use({...}) inside a test.describe() block — Playwright forbids this and it will crash the entire test suite. test.use() MUST always be at the top level of the file, before any test.describe() call

## SPA / Multi-Step Wizard Handling

For JavaScript SPA sites, read IMPL_SUMMARY "Required Interaction Sequence" carefully. If the IMPL_SUMMARY documents required steps before the primary CTA (e.g. decline AppleCare, select payment type), you MUST:
1. Create Page Object methods for each required intermediate step (e.g. `declineAppleCareIfPresent()`, `dismissCountryDialogIfPresent()`)
2. Guard each with `isVisible(...).catch(() => false)` so they are safe to call even if the step is not present
3. Call these methods BEFORE asserting the CTA is enabled and BEFORE clicking it
4. NEVER write `expect(button).toBeEnabled()` directly after navigation to a SPA — always complete all required wizard steps first

For heading assertions on SPA sites: `page.locator('h1, h2').first()` picks navigation submenu headings that appear first in DOM order. Always use `page.locator('main h1').first()` or `page.locator('[role="main"] h1').first()` to target page content headings only.

For bag/cart counter assertions: parse the aria-label with a generic digit match (`label.match(/(\d+)/)`), NOT an end-anchored match, since the label format varies by site and item count.
